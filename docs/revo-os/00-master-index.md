## 命名ルール（2026-07-15 制定）

| 対象 | ルール | 例 |
|---|---|---|
| フォルダ | `番号_日本語名`。01〜08は業務の流れ順、99は保管庫 | `04_事務サポ` |
| ふつうの資料 | 日本語で内容がわかる名前 ＋ `.md` | `税計算仕様.md` |
| 日付が大事な記録 | `名前_YYYY-MM-DD.md` | `監査報告書_2026-07-15.md` |
| SOP | `SOP-3けた番号_内容.md` | `SOP-001_開発コマンド一覧.md` |
| 版の管理 | ファイル名に「v2」「最終」「コピー」を付けない。**同じファイルを直す**（履歴はGitが持つ） | — |
| 99_保管庫の中 | **当時のまま凍結**。このルールの対象外 | `12-tax-test-result.txt` |
| アプリのコード（src/） | 開発ツールの決まりに従う。このルールの対象外 | `page.tsx` |

## 運用ルール

1. **分類先の判断**: 経営判断＝01、相談窓口＝02、集客＝03、案件管理アプリ＝04、知識蓄積＝05、手順書＝06、自動化計画＝07、対外説明＝08、終わった記録＝99。
2. **重複禁止**: 同じ内容を2か所に置かない。どうしても載せる場合は片方を「正本」と明記し、もう片方に「写し・正本はこちら」と書く（例: 自動化ロードマップ）。
3. **READMEの維持**: フォルダに資料を足したら、そのフォルダのREADMEの表にも1行足す。
4. **インデックス更新**: 資料の追加・移動・削除をしたら、本ファイルも更新する。
5. **保管庫は凍結**: 99_保管庫の中身は名前も本文も書き換えない。
