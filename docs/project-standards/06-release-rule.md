# 06. リリース・バージョン規格

AI棟梁 運用規格 Ver1.0 / 分類：JIMU

## バージョン表記

```
vメジャー.マイナー   （例：v1.0, v1.1, v2.0）
```

- **メジャー** … 大きな機能追加・データ構造の変更・画面構成の刷新。
- **マイナー** … 小さな機能追加・不具合修正・改善。

資料・規格・ロードマップも同じ表記を使う（例：本規格は Ver1.0）。

## 事務サポ（JIMU）のリリース段階

事務サポは Phase1 完成までは**内部リリースのみ**。外部公開・宣伝はしない。

| 段階 | 内容 | 版の目安 |
|------|------|---------|
| 内部開発版 | 開発中。`review/draft-save` 上で統合・検証。 | v0.x |
| Phase1 完成版 | 事務サポの基本業務（案件→見積→請求→帳票）が実運用に耐える。 | v1.0 |
| 以降 | 職人30人・元請機能・大量案件対応を段階追加。 | v1.x → v2.0 |

Phase 定義とゲート条件は [../roadmap/JIMU-Roadmap-v1.0.md](../roadmap/JIMU-Roadmap-v1.0.md) を参照。

## リリース前チェックリスト（各版共通）

1. `npm run build` 成功（本番ビルド設定は不用意に変えない）
2. `npx tsc --noEmit` 成功
3. 主要導線の通しテスト（案件登録→工事項目→見積→請求→帳票）
4. 既存データ互換（旧キーを壊さない・移行は非破壊）
5. スマホ幅（375 / 390 / 430px）でレイアウト破綻がない
6. 変更ファイル・検証結果・残リスクを `verification/` に記録
7. コミット規則（03）に沿ったコミット・SHA 記録

## AI棟梁のリリース（別扱い・未公開）

AI棟梁は事務サポとは**別のリリース判断**で進める。以下を厳守。

- 事務サポ完成前は UI/メニュー/β表示のいずれにも出さない。
- 案件**1000件**到達後に内部評価を開始。
- 案件**3000件**で精度検証。
- 案件**5000件**で公開可否を判断。
- 上記に達するまで、AI棟梁の機能はデータ設計の先行整備に留める。
