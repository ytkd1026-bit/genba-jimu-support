# 08. チャット・情報分類規格（ChatGPT / Claude / Notion / Google Drive 共通）

AI棟梁 運用規格 / 分類：JIMU・AIT・REVO・KNOW / **版：Ver1.1** / 更新：2026-07-12
（初版 Ver1.0：2026-07-12 → 変更履歴は [09-chat-classification-changelog.md](./09-chat-classification-changelog.md)）

## この規格の目的

**ソフト開発ではなく、情報管理の標準化**が目的。
ChatGPT・Claude・Notion・Google Drive で扱う会話履歴・資料・タスクを、
同じ分類・優先度・状態・命名規則で管理し、
どのツールへ移してもそのまま使える共通フォーマットを定める。

## 1. ワーク分類（4分類）

| コード | 名称 | 対象 |
|--------|------|------|
| **JIMU** | 現場の事務サポ | アプリ開発・GitHub・URL・バグ修正・見積/請求/材料管理（＝機能実装） |
| **REVO** | REVO経営 | 事業計画・資金調達・営業・利益率・単価表・保険修繕（＝経営/金/業務そのもの） |
| **AIT** | AI棟梁 | 施工ノウハウ・現場写真（教材/蓄積）・教育資料・職人育成・現場データベース（施工知見） |
| **KNOW** | 共通ナレッジ | 特定事業に属さない汎用知識・ツール活用・調べ物（例：Notion/Gitの使い方、AI活用術、税務や法務の一般調査、テンプレート） |

> **KNOW の判定**：JIMU/REVO/AIT のどれか1事業の価値に直結すればそちらへ。
> どの事業にも紐づかない横断的な知識・道具・調べ物は KNOW。
> 「あとで別の事業に効くかも」程度なら KNOW に置き、事業が定まった時点で移す。

## 2. 優先度（時間軸で定義）

| コード | 意味（いつやるか） |
|--------|--------------------|
| **S** | 今週（今週中に動く） |
| **A** | 今月（今月中に動く） |
| **B** | 今年（今年のうちに） |
| **C** | 保留（時期未定・様子見） |
| **X** | 破棄（やらない・不要） |

> 優先度は「**いつ着手するか（時間軸）**」を表す。進行状況は「状態」（3）で別に持つ。
> この2軸は独立：例）状態=DOING でも優先度=A（今月中）はあり得る。

## 3. 状態（7状態・ライフサイクル）

| 状態 | 意味 |
|------|------|
| **IDEA** | 思いつき・構想。まだタスク化していない種 |
| **TODO** | 着手予定。やることが定まった |
| **DOING** | 進行中。今まさにやり取り・作業している |
| **WAIT** | 相手待ち（返信・承認・外部要因）で自分の手は離れている |
| **HOLD** | 自分都合で保留（仕様未確定・優先度低下で止めた） |
| **DONE** | 完了。結論が出た |
| **ARCHIVE** | 保管・凍結。参照はするが動かさない（完了後の長期保管や廃止確定） |

### 状態遷移（目安）

```
IDEA → TODO → DOING → DONE → ARCHIVE
                ↑ ↓
            WAIT / HOLD
```

- **WAIT と HOLD の違い**：WAIT は「他者・外部待ち」、HOLD は「自分の判断で保留」。
- **DONE と ARCHIVE の違い**：DONE は結論が出た直後、ARCHIVE は長期保管/凍結。
- 逆行（DONE→DOING 等）は原則せず、追加分は新しいチャット/タスクを起こす。

## 4. ChatGPT / Claude チャット命名規則

```
分類-YYYYMMDD-内容
```

例：

```
JIMU-20260712-下書き保存バグ
REVO-20260712-事業計画ドラフト
AIT-20260712-クロス施工手順
KNOW-20260712-Notion整理術
```

- 分類は **JIMU / REVO / AIT / KNOW**（大文字）。
- 日付は会話開始日または主題確定日（8桁 YYYYMMDD）。
- 内容は簡潔に・半角スペースを使わない（区切りは `・` か `_`）。

## 5. ファイル命名規則（資料・エクスポート）

```
分類-日付-内容-v版数.拡張子
```

例：`JIMU-20260712-チャット分類表-v1.1.csv`（詳細は 02 参照）
チャット名（4）は版数なし、成果物ファイル（5）は版数ありが原則。

## 6. 判定ルール（タイトルから 分類・優先度・状態 を決める）

### 6-1. 分類の一次判定（キーワード）

| 分類 | 一次キーワード |
|------|----------------|
| **JIMU** | アプリ, 開発, GitHub, PR, ブランチ, デプロイ, Vercel, URL, バグ, エラー, 500, ビルド, Next, React, UI, 画面, 下書き, PDF, スマホ, Safari, 見積“機能”, 請求“機能”, 材料管理“機能” |
| **REVO** | 事業計画, 資金調達, 融資, 営業, 顧客開拓, 利益率, 粗利, 単価表, 料金, 保険修繕, 保険申請, 経営, 資金繰り |
| **AIT** | 施工, ノウハウ, 手順, 事例, クロス貼替, 現場写真（蓄積/教材）, 教育, 資料, 職人育成, 歩掛, 現場データベース（施工知見） |
| **KNOW** | 使い方, 入門, 基礎, ツール, テンプレート, AI活用, プロンプト, 一般調査, 税務/法務の基礎, ショートカット（＝特定事業に属さない汎用知識） |

### 6-2. あいまい時の決め手（目的で判定）

「その会話が**最終的にどの事業価値になるか**」で決める（01と同じ）。

- **見積・単価**：アプリの見積“機能”を作る → JIMU／単価・利益率・料金そのもの → REVO
- **現場写真**：写真台帳“画面/機能” → JIMU／ノウハウ蓄積・AI教材化 → AIT
- **保険**：保険修繕の業務・申請 → REVO／保険案件“画面”の実装 → JIMU
- **データベース**：アプリの保存/DB実装 → JIMU／施工知見の現場DB → AIT
- **ツール・使い方**：特定事業の作業手順 → その事業／汎用の道具知識 → KNOW
- **重複時の強さ順：JIMU（実装語）＞ REVO（金・経営語）＞ AIT（知見語）＞ KNOW（汎用）**
- 判定材料が乏しい単発の調べ物は既定で **KNOW / C / IDEA**（事業が定まったら移す）

### 6-3. 優先度の判定（時間軸）

- 今週動く → **S**／今月動く → **A**／今年のうち → **B**／時期未定 → **C**／不要 → **X**

### 6-4. 状態の判定

- 構想の種 → **IDEA**／着手予定 → **TODO**／作業中 → **DOING**／相手待ち → **WAIT**／
  自分都合で保留 → **HOLD**／完了 → **DONE**／長期保管・凍結 → **ARCHIVE**

## 7. CSV出力仕様

チャット履歴・情報の棚卸しは、次の列を持つ CSV で出力する。

| 列 | 内容 |
|----|------|
| チャット名 | 元のタイトル（または命名規則へ整えた名） |
| 分類 | JIMU / REVO / AIT / KNOW |
| 優先度 | S / A / B / C / X |
| 状態 | IDEA / TODO / DOING / WAIT / HOLD / DONE / ARCHIVE |
| 理由 | 判定根拠（どのキーワード・決め手で分類したか） |

### CSVの約束（ツール間共通利用のため）

- 文字コード **UTF-8**、1行目はヘッダ固定。
- 値にカンマ・改行を含む場合は**ダブルクォートで囲む**（RFC 4180 準拠）。
- 列の順序・名称は固定（`チャット名,分類,優先度,状態,理由`）。
- 分類・優先度・状態は**必ず定義済みコードのみ**（表記ゆれ禁止）。

## 8. 全ツール共通利用（ChatGPT / Claude / Notion / Google Drive）

この5列CSVは、4ツールすべてで同じコード体系のまま取り込めることを前提に設計する。

| ツール | 使い方 |
|--------|--------|
| **ChatGPT** | プロジェクト/フォルダを分類（JIMU/REVO/AIT/KNOW）で分け、チャット名を命名規則（4）に揃える |
| **Claude** | 同上。プロジェクト単位で分類を分け、成果物ファイルは命名規則（5） |
| **Notion** | CSVをDBインポート。分類/優先度/状態は Select プロパティ、理由は Text。ビューを分類別・優先度別に |
| **Google Drive** | フォルダを分類で分け、ファイルは命名規則（5）。この CSV を棚卸し台帳として保管 |

### 拡張時の互換ルール

- 5列は**削除・改名しない**（後方互換の核）。追加情報は**末尾に列を足す**だけ。
- コード値（分類4・優先度S〜X・状態7）は本規格を唯一の定義とし、ツール側で勝手に増やさない。
  増やす場合は本規格の版を上げ、[09-chat-classification-changelog.md](./09-chat-classification-changelog.md) に記録する。
- 将来 AI棟梁DB へ載せる際は 5列＋（chat_id / created_at / tenant_id）を末尾追加（07 のギャップ指針に沿う）。
