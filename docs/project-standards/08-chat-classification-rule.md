# 08. チャット・情報分類規格（ChatGPT / Claude / AI棟梁 共通）

AI棟梁 運用規格 Ver1.0 / 分類：JIMU・AIT・REVO / 版：v1.0 / 作成：2026-07-12

## この規格の目的

**ソフト開発ではなく、情報管理の標準化**が目的。
ChatGPT・Claude・将来の AI棟梁 が扱う会話履歴・資料・タスクを、
同じ分類・優先度・状態・命名規則で管理し、
ChatGPTワーク / Notion / Google Drive / AI棟梁DB のどこへ移しても
そのまま使える共通フォーマットを定める。

関連：[01-project-classification.md](./01-project-classification.md)（分類コードの定義） /
[04-priority-rule.md](./04-priority-rule.md) / [05-status-rule.md](./05-status-rule.md) /
[02-file-naming-rule.md](./02-file-naming-rule.md)

## 1. ワーク分類

| コード | 名称 | 対象 |
|--------|------|------|
| **JIMU** | 現場の事務サポ | アプリ開発・GitHub・URL・バグ修正・見積/請求/材料管理（＝機能実装） |
| **AIT** | AI棟梁 | 施工ノウハウ・現場写真（教材/蓄積）・教育資料・職人育成・現場データベース（施工知見） |
| **REVO** | REVO経営 | 事業計画・資金調達・営業・利益率・単価表・保険修繕（＝経営/金/業務そのもの） |

## 2. 優先度

| コード | 意味 | 情報管理での定義 |
|--------|------|------------------|
| **S** | 最優先 | 今まさに業務/開発が止まる・直結する（現行バグ、請求・入金、データ消失、進行中の資金調達・営業） |
| **A** | 高 | Phase1完成や事業に必須の主要テーマ（主要機能開発、事業計画、単価表整備） |
| **B** | 中 | あると役立つ改善・将来のノウハウ・教材（施工事例、教育資料、UX改善） |
| **C** | 低 | 参考・アイデア・単発の調べ物・雑多 |
| **X** | 廃止候補 | 古い・方針転換で不要・重複。アーカイブ/削除の棚卸し対象 |

## 3. 状態

| 状態 | 意味 |
|------|------|
| **TODO** | 未着手。これから扱う会話・タスク |
| **DOING** | 進行中。今まさにやり取り・作業している |
| **HOLD** | 保留。依存待ち・仕様未確定で止めている |
| **DONE** | 完了。結論が出て、以降は参照のみ |

状態遷移：`TODO → DOING → DONE`（保留は `HOLD`。詳細は 05 参照）

## 4. ChatGPT / Claude チャット命名規則

```
分類-YYYYMMDD-内容
```

例：

```
JIMU-20260712-下書き保存バグ
AIT-20260712-クロス施工手順
REVO-20260712-事業計画ドラフト
```

- 分類は **JIMU / AIT / REVO**（大文字）。
- 日付は会話開始日または主題確定日（8桁 YYYYMMDD）。
- 内容は簡潔に・半角スペースを使わない（区切りは `・` か `_`）。

## 5. ファイル命名規則（資料・エクスポート）

```
分類-日付-内容-v版数.拡張子
```

例：`JIMU-20260712-チャット分類表-v1.0.csv`（詳細は 02 参照）

チャット名（4）は版数なし、成果物ファイル（5）は版数ありが原則。

## 6. 判定ルール（タイトルから 分類・優先度・状態 を決める）

### 6-1. 分類の一次判定（キーワード）

| 分類 | 一次キーワード |
|------|----------------|
| **JIMU** | アプリ, 開発, GitHub, PR, ブランチ, デプロイ, Vercel, URL, バグ, エラー, 500, ビルド, Next, React, UI, 画面, 下書き, PDF, スマホ, Safari, 見積“機能”, 請求“機能”, 材料管理“機能” |
| **AIT** | 施工, ノウハウ, 手順, 事例, クロス貼替, 現場写真（蓄積/教材）, 教育, 資料, 職人育成, 歩掛, 現場データベース（施工知見） |
| **REVO** | 事業計画, 資金調達, 融資, 営業, 顧客開拓, 利益率, 粗利, 単価表, 料金, 保険修繕, 保険申請, 経営, 資金繰り |

### 6-2. あいまい時の決め手（目的で判定）

「その会話が**最終的にどの事業価値になるか**」で決める（01と同じ）。

- **見積・単価**：アプリの見積“機能”を作る → JIMU／単価・利益率・料金そのもの → REVO
- **現場写真**：写真台帳“画面/機能” → JIMU／ノウハウ蓄積・AI教材化 → AIT
- **保険**：保険修繕の業務・申請 → REVO／保険案件“画面”の実装 → JIMU
- **データベース**：アプリの保存/DB実装 → JIMU／施工知見の現場DB → AIT
- **重複時の強さ順：JIMU（実装語）＞ REVO（金・経営語）＞ AIT（知見語）**
- 判定材料が乏しいタイトルは既定で **JIMU / C / TODO**（後で中身を見て再分類）

### 6-3. 優先度の判定

- 現行バグ・請求/入金・データ消失・進行中の資金調達/営業 → **S**
- 主要機能開発・事業計画・単価表整備 → **A**
- 改善・ノウハウ・教材 → **B**
- 参考・アイデア・単発 → **C**
- 古い・重複・方針転換で不要 → **X**

### 6-4. 状態の判定

- これから／積んだだけ → **TODO**
- 今やり取り中・作業中 → **DOING**
- 依存待ち・仕様未確定で停止 → **HOLD**
- 結論が出て参照のみ → **DONE**

## 7. CSV出力仕様

チャット履歴・情報の棚卸しは、次の列を持つ CSV で出力する。

| 列 | 内容 |
|----|------|
| チャット名 | 元のタイトル（または命名規則へ整えた名） |
| 分類 | JIMU / AIT / REVO |
| 優先度 | S / A / B / C / X |
| 状態 | TODO / DOING / HOLD / DONE |
| 理由 | 判定根拠（どのキーワード・決め手で分類したか） |

### CSVの約束（ツール間共通利用のため）

- 文字コード **UTF-8**、1行目はヘッダ固定。
- 値にカンマ・改行を含む場合は**ダブルクォートで囲む**（RFC 4180 準拠）。
- 列の順序・名称は固定（`チャット名,分類,優先度,状態,理由`）。
- 分類・優先度・状態は**必ず定義済みコードのみ**（表記ゆれ禁止）。

サンプル：[../../verification/project-standardization/06-chat-classification-example.csv](../../verification/project-standardization/06-chat-classification-example.csv)（20件以上）

## 8. 将来対応（ChatGPTワーク / Notion / Google Drive / AI棟梁DB 共通）

この5列CSVは、そのまま各ツールへ取り込めることを前提に設計する。

| 連携先 | 使い方 |
|--------|--------|
| **ChatGPTワーク（プロジェクト）** | 分類ごとにプロジェクトを分け、チャット名を命名規則（4）に揃える |
| **Notion** | CSVをデータベースとしてインポート。分類/優先度/状態は Select プロパティ、理由は Text |
| **Google Drive** | フォルダを分類（JIMU/AIT/REVO）で分け、ファイルは命名規則（5）。CSVを台帳として保管 |
| **AI棟梁DB** | 5列を DB カラムへ（分類→category, 優先度→priority, 状態→status, 理由→note）。将来は chat_id / created_at / tenant_id を付与（07 のギャップ指針に沿う） |

### 拡張時の互換ルール

- 5列は**削除・改名しない**（後方互換の核）。
- 追加が必要な情報（日付・ID・タグ等）は**末尾に列を足す**だけにする。
- コード値（JIMU/AIT/REVO・S〜X・4状態）は本規格を唯一の定義とし、
  ツール側で勝手に増やさない。増やす場合は本規格の版を上げる。

> 機能・UI・メニュー・β表示のいずれにも露出させない（06・ロードマップ参照）。
