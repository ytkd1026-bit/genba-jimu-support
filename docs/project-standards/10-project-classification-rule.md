# 10. 案件分類規格 Ver1.0

AI棟梁 運用規格 / 分類：JIMU・REVO / **版：Ver1.0** / 作成：2026-07-12
位置づけ：**内部設計（ドキュメントのみ・実装なし）**。AI棟梁は未公開のため UI/メニュー/β機能に出さない。

## 目的

案件を**複数の軸**で一貫分類し、ChatGPT / Claude / Notion / Google Drive / AI棟梁DB /
現場の事務サポ の全てで同じコード体系で扱えるようにする。
ご提示の例（保険・原状回復・分譲マンション・戸建・店舗・メンテナンス・クロス・CF・FT・
長尺・シート・カーテン・ブラインド）は**軸が混在**しているため、下記の軸に整理する。

> 根拠の凡例：`✅実装済`＝既存コードに定義あり（file:line 明記）／
> `🟡内部設計`＝本規格で新設・アプリ未実装（将来タスク）。推測は用いない。

## 1. 分類の軸（多軸）

案件は「種別 × 保険種別 × 建物 × 工事種別 × 工事内容 × 材料/仕上げ」で表す。
各軸は独立。1案件が各軸から0〜複数を持つ（材料などは複数可）。

## 2. 案件分類の表記（タグ形式）

チャット名・ファイル名・CSV では、軸をコロン区切りのタグで表す（複数はセミコロン区切り）。

```
種別:保険; 保険種別:水漏れ; 建物:分譲マンション; 工種:原状回復; 内容:内装工事; 材料:クロス;CF
```

- 事務サポの案件データと突き合わせる際は **project_id（例 REV-2026-0001）** を主キーにする
  （src/app/utils/idGenerator.ts:11,59-64）。
- 分類タグは AI棟梁DB（12）の `tags` / 各軸カラムへそのまま載る。

## 3. 判定の原則

- **軸を混同しない**。「保険」は種別軸、「分譲マンション」は建物軸、「原状回復」は工種軸、
  「クロス/CF」は材料軸。1つの案件が各軸から値を持つ。
- 迷ったら「その情報がどの軸の問いに答えるか」（誰の家？＝建物、何の工事？＝工種、何を貼る？＝材料）。
- 既存コードに無い値（雪害・落雷・メンテナンス・材料軸）は🟡内部設計。
  実装は将来タスクで、本ドキュメントを唯一の定義とする。
