# 04. 優先度規格

AI棟梁 運用規格 Ver1.0 / 分類：JIMU

タスク・要望・不具合には必ず優先度を1つ付ける。

## 優先度一覧

| コード | 意味 | 定義 | 目安 |
|--------|------|------|------|
| **S** | 最優先 | これが無いと業務／開発が止まる。データ消失・500・入金や請求に関わる不具合。 | 即着手 |
| **A** | 高 | Phase1（事務サポ完成）に必須。主要導線・帳票・保存。 | 今スプリント |
| **B** | 中 | あると業務が楽になる改善。無くても Phase1 は完成する。 | 次スプリント以降 |
| **C** | 低 | 将来的にやりたい。細かなUX・見た目・省力化。 | 手が空いたら |
| **X** | 廃止候補 | 使われていない／方針転換で不要になった。削除・凍結を検討。 | 棚卸し対象 |

## 付け方の指針

- **S の乱発を避ける**。「本当に業務が止まるか？」で判定する。
  入力データ消失・請求金額の誤り・案件が開けない等が S。
- Phase1 の完成条件（ロードマップ参照）に直結するものは最低 **A**。
- 「AI棟梁」に関わる項目は、公開条件（案件1000/3000/5000件）に達するまで
  原則 **C 以下**。先行してデータ設計だけ進める場合も UI 露出は禁止。
- **X** はすぐ消さず、まず X を付けて棚卸しリストに載せ、影響確認後に削除。

## 表記例

```
[JIMU][S] 案件登録の入力消失を防ぐ（下書きフラッシュ保存）
[JIMU][A] 請求書スナップショットの再表示
[JIMU][B] 一括請求の税区分対応
[REVO][C] 単価表マスタのCSV取込
[AIT][C] 施工事例のタグ付けUI（※AI棟梁公開まで非表示）
[JIMU][X] 旧見積サンプル画面の撤去検討
```
