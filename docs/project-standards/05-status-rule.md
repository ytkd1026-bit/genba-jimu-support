# 05. 状態規格

AI棟梁 運用規格 Ver1.0 / 分類：JIMU

タスクの進行状態は下記4つで表す。

## 状態一覧

| 状態 | 意味 | 遷移の目安 |
|------|------|-----------|
| **TODO** | 未着手。合意済みでこれからやる。 | 着手したら DOING |
| **DOING** | 着手中。担当と着手日が決まっている。 | 完了・検証で DONE、止まったら HOLD |
| **HOLD** | 保留。依存待ち・仕様未確定・優先度低下で一時停止。 | 再開したら DOING |
| **DONE** | 完了。build/型/テストが通り、検証済み。 | 原則戻さない |

## 状態遷移

```
TODO → DOING → DONE
          ↓ ↑
         HOLD
```

- 逆行（DONE → DOING 等）は原則しない。追加作業が出たら**新しいタスク**を起こす。
  （マージ済み PR に積み増さない、という Git 運用と同じ考え方）

## 各状態の必須情報

- **TODO** … 分類・優先度・完了条件（何を満たせば DONE か）。
- **DOING** … 担当・着手日・対象ブランチ（`feature/jimu-*` 等）。
- **HOLD** … 保留理由・再開条件（何が解決したら動くか）。
- **DONE** … 検証結果（build/型/テスト）・コミットSHA・確認/未確認の別。

## DONE の定義（Definition of Done）

以下をすべて満たしたときのみ DONE にできる。

1. `npm run build` 成功
2. `npx tsc --noEmit` 成功
3. 該当機能の動作確認（可能な範囲で実機／エミュレーション）
4. **未確認項目を「成功」と書かない**（未確認は「未確認」と明記）
5. コミット済み（コミットSHA を記録）

## 表記例

```
[JIMU][A][DONE]  請求書スナップショット再表示  (SHA: 25e7559)
[JIMU][S][DOING] 実機Safariでの下書き保持確認   branch: fix/jimu-draft-save
[JIMU][B][HOLD]  一括請求の税区分対応（単体フロー確定待ち）
[JIMU][C][TODO]  案件ログ入力画面の実装
```
