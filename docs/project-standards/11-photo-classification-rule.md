# 11. 写真分類規格 Ver1.0

AI棟梁 運用規格 / 分類：JIMU・AIT / **版：Ver1.0** / 作成：2026-07-12
位置づけ：**内部設計（ドキュメントのみ・実装なし）**。AI棟梁は未公開のため UI/メニュー/β機能に出さない。

## 目的

現場写真を統一区分で分類し、事務サポの写真台帳・AI棟梁の施工ノウハウ／安全管理・
現場データベースで同じコードで扱えるようにする。

> 根拠の凡例：`✅実装済`＝既存 enum に定義あり（file:line）／`🟡内部設計`＝本規格で新設・未実装。

## 1. 写真区分（9分類）

| コード | ラベル | 用途 | 根拠 |
|--------|--------|------|------|
| `before` | 施工前 | 着工前の状態記録・見積根拠 | ✅実装済 `PHOTO_PHASE_LABELS.before="施工前"`（src/app/utils/photoRecords.ts:38-46） |
| `during` | 施工中 | 工程・下地・中間検査 | ✅実装済 `.during="施工中"` 同上 |
| `after` | 施工後 | 完了・仕上がり確認 | ✅実装済 `.after="完了"` 同上（ラベルは「完了」＝施工後） |
| `defect` | 不具合 | 不具合・欠陥・是正前 | 🟡内部設計（既存 enum に無い） |
| `cause` | 原因 | 原因箇所（漏水元・劣化起点） | ✅実装済 `.cause="原因箇所"` 同上 |
| `measure` | 対策 | 是正・補修の対応内容 | 🟡内部設計（既存 enum に無い） |
| `material` | 材料 | 使用材料・製品ラベル・数量 | 🟡内部設計（既存 enum に無い） |
| `tool` | 工具 | 使用工具・機材 | 🟡内部設計（既存 enum に無い） |
| `safety` | 安全 | 安全管理・KY・脚立・足場・危険箇所 | 🟡内部設計（今回追加） |

> 既存 enum には他に `survey="現調"` / `dimension="寸法"` / `other="その他"` もある
> （photoRecords.ts:38-46）。本規格の9分類と併存させ、
> `survey` は「施工前」の下位、`dimension` は「材料/対策」の補助、`other` は受け皿として運用する。

### 「安全」区分の意図（今回追加）
AI棟梁で**安全管理・KY（危険予知）・脚立・足場・危険箇所分析**に利用するための独立区分。
施工の良し悪し（before/during/after）とは別軸で、安全に関する写真を確実に拾えるようにする。

## 2. 写真分類の表記

- 事務サポの写真台帳とは **photo_id（例 P-001）** で対応（src/app/utils/photoRecords.ts:23,
  idGenerator.ts:67-80）。
- 案件との対応は **project_id**、被害との対応は **damage_id（D-001）** を保持（既存の
  PhotoRecord.projectId / damageId、photoRecords.ts:24-25）。
- 分類コードは AI棟梁DB（12）の `photo_category` カラム／`tags` に載る。

CSV・タグ例：
```
project_id:REV-2026-0001; photo_id:P-003; 区分:安全; 場所:3階足場; 説明:手すり未設置の是正前
```

## 3. 判定の原則

- 施工の時系列は `before → during → after`。問題系は `defect（不具合）→ cause（原因）→ measure（対策）`。
- 記録対象が「モノ」なら `material（材料）`／`tool（工具）`。
- 安全に関わるものは内容を問わず `safety（安全）` を優先付与（KY・足場・脚立・危険箇所）。
- 1枚が複数に該当する場合は主区分1つ＋補助タグで表す（例：主=`safety`, 補=`defect`）。
