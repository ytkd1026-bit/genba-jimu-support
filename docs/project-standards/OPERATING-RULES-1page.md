# 今後 私が守る運用ルール（1ページ）

AI棟梁 情報管理標準 / 現行正式版：チャット分類 **Ver1.1** ・案件/写真/DB **Ver1.0** / 2026-07-12

## 1. まず「4分類」を付ける
すべての会話・資料・タスクに1つ。
- **JIMU**＝事務サポ開発 / **REVO**＝経営・お金 / **AIT**＝施工ノウハウ・AI棟梁 / **KNOW**＝汎用ナレッジ
- 迷ったら強さ順 **JIMU＞REVO＞AIT＞KNOW**。判定材料が薄い単発は **KNOW**。

## 2. 「優先度（いつやる）」と「状態（今どこ）」を分けて付ける
- 優先度：**S=今週 / A=今月 / B=今年 / C=保留 / X=破棄**
- 状態：**IDEA→TODO→DOING→DONE→ARCHIVE**（外部待ち=**WAIT** / 自分都合の保留=**HOLD**）

## 3. 名前を規則どおりに付ける
- チャット：`分類-YYYYMMDD-内容`（例 `JIMU-20260712-下書き保存バグ`）
- ファイル：`分類-日付-内容-v版数`（例 `REVO-20260712-単価表-v1.0.csv`）
- 半角スペースは使わない（区切りは `・` か `_`）。

## 4. 案件は「軸」で分ける（混同しない）
種別(通常/保険) × 保険種別(火災/水漏れ/風災/雪害/落雷/他) × 建物(分譲/戸建/店舗…) ×
工種(原状回復/メンテ…) × 内容(内装/美装…) × 材料(クロス/CF/FT/長尺/シート/カーテン/ブラインド)。
- 案件はすべて **project_id（REV-2026-0001）** で串刺しにする。

## 5. 写真は「9区分」で撮る・仕分ける
施工前 / 施工中 / 施工後 / 不具合 / 原因 / 対策 / 材料 / 工具 / **安全**
- 安全（KY・脚立・足場・危険箇所）は内容問わず優先的に付ける。

## 6. Git・開発のとき
- ブランチ：`feature/jimu-内容` / `fix/jimu-内容`。**基準ブランチへ勝手に merge しない**。
- コミット：`feat: / fix: / refactor: / docs: / test:`。
- 「完了(DONE)」は **build成功・型OK・確認済み**が条件。**未確認を「成功」と書かない**。

## 7. CSVで棚卸しする（全ツール共通）
列は固定：`チャット名, 分類, 優先度, 状態, 理由`（UTF-8・カンマ入りは""で囲む）。
- この5列は削除・改名しない。増やすときは**末尾に追加**するだけ。
- ChatGPT / Claude / Notion / Google Drive のどこでも同じコードで使う。

## 8. AI棟梁は「まだ出さない」
- UI・メニュー・β機能に**出さない**。分類やDBは**内部設計として先に整えるだけ**。
- 内部評価は案件**1000件**から、精度検証**3000件**、公開可否判断**5000件**。

---
**要するに毎回：**「①4分類 → ②優先度(いつ)＋状態(どこ) → ③規則どおりの名前」を付ける。
案件は project_id で串刺し、写真は9区分、開発は feature/fix ブランチ＋docsコミット。AI棟梁は内部だけ。
