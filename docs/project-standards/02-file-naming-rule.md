# 02. ファイル命名規則

AI棟梁 運用規格 Ver1.0 / 分類：JIMU

## 基本形

```
分類-YYYYMMDD-内容-v版数.拡張子
```

| 要素 | 規則 | 例 |
|------|------|-----|
| 分類 | REVO / AIT / JIMU（大文字） | `JIMU` |
| YYYYMMDD | 作成日または版の確定日（8桁） | `20260712` |
| 内容 | 日本語可・簡潔に・空白は使わない | `下書き保存` |
| v版数 | `v` + メジャー.マイナー | `v1.0` |
| 拡張子 | `.md` `.pdf` `.png` `.csv` など | `.md` |

## 例

```
REVO-20260712-事業計画書-v1.0.pdf
AIT-20260712-クロス施工事例-v1.0.md
JIMU-20260712-下書き保存-v1.0.md
```

## 版数の上げ方

- **軽微な追記・誤字修正** … マイナーを上げる（v1.0 → v1.1）
- **構成・結論が変わる改訂** … メジャーを上げる（v1.1 → v2.0）
- 版を上げたら旧ファイルは削除せず残す（履歴として保持）。

## 区切り・文字の約束

- 要素の区切りは半角ハイフン `-`。
- 「内容」の中で語を区切りたいときは全角中黒 `・` かアンダースコア `_`。
  半角スペースは使わない（URL・シェルで壊れるため）。
- 日付は必ず `YYYYMMDD` の8桁（`2026-07-12` や `2026/7/12` にしない）。

## リポジトリ内のソースコードについて

この命名規則は**資料・ドキュメント・データ成果物**に適用する。
アプリのソースコード（`.ts` / `.tsx`）は Next.js / React の慣習
（ケバブケースのルート、パスカルケースのコンポーネント）を優先し、
この規則は適用しない。

## 迷ったときの原則

- 未来の自分・別のAI・別の担当者が、**ファイル名だけで中身と鮮度を判断できる**こと。
- 「分類」「いつの」「何の」「第何版」の4点が読み取れれば正しい。
